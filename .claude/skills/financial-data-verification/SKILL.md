# Financial Data Verification — 数字が「標準の定義どおりか」を潰す

`financial-analyst-review` が**何の数字か**を問うのに対し、これは**その数字が正しく
取れているか**を問う。順番は本スキルが先、レビューが後。

**原則: 検証していない数字は報告しない。検証が「比較対象なし」で通ったものは、
合格ではなく沈黙である。**

---

## 0. 出典の階層 — 上位が下位に勝つ

| 順位 | 出典 | 使うもの |
|---|---|---|
| 1 | **通期決算短信 PDF** | 貸借対照表・損益計算書・CF計算書・セグメント情報・特別損益 |
| 2 | 四半期決算短信 PDF | 貸借対照表のみ(**注記は載っていない**) |
| 3 | Kabutan | 株価指標(PER/PBR/時価総額)、業績推移、CF推移 — **突合用の独立ソース** |
| 4 | Yahoo!ファイナンス chart API | 株価履歴 |

- 有価証券報告書は EDINET 側で Yahoo の TDnet ミラーには無い。
  **通期短信で代替できる**(`find_annual_tanshin`)。
- 開示一覧は1ページ約34件。12月期決算は `?page=2` 以降。
- **上位ソースがあるのに下位で済ませない。** 四半期短信しか読まずに「注記は取得不可」と
  書くのは誤り(実際にやった)。

## 1. 単位 — 最も静かに壊れる

- `単位：百万円` / `千円` は**そのページから**読む。前のページの単位を引き継ぐのは
  改ページした連結BSのときだけ。文書内の最初の一致を使うと1000倍ずれる。
- **実例:** 5367 を千円→百万円と読み違え、Net Cash Ratio が 0.532 ではなく **538倍**に
  なった。しかも PER/PBR/時価総額の突合は**全部通った**(それらはBSに触れないため)。
- IFRS は単位表記が `百万円 百万円` のような列見出しだけのことがある。

## 2. 勘定科目 — 行頭アンカーと表形式の判定

- **行頭に錨を打つ。** `負債合計` は `流動負債合計`・`固定負債合計` の部分文字列。
  アンカーなしだと小計を拾って比率がもっともらしく間違う。
- **表の行か散文かを判定する。** ラベルの後が数字だけなら行、文字が続けば散文。
  実例: 1848 の MD&A `負債合計は23,714百万円となり、…1,244百万円の増加` を行として読み、
  文中の 1,244 を負債合計にしていた。
- **小さい数字を捨てない。** 桁数の下限を設けると1,000未満が消える。
  実例: 1848 の `投資有価証券 173` が消え、**「取得不可」と誤報告**した。
  「取得不可」は事実の主張なので、見つからなかっただけで書いてはいけない。
- **増減列に注意。** 3列目が差分のことがある。`|(b-a)-c| ≈ 0` で判定し、**符号付きで**
  比較する(符号を落とすと減少年の差分列を見逃す)。
- **合算科目に注意。** `営業保証金・破産債権` のように別物が1行のことがある。

## 3. 恒等式 — ただし「通っても意味がない」場合を知る

必ず確認:
- `資産合計 = 負債合計 + 純資産合計`
- `流動資産合計 + 固定資産合計 = 資産合計`
- `フリーCF = 営業CF + 投資CF`
- `投資有価証券 ≤ 投資その他の資産合計`(比率の入力で唯一、恒等式が覆わない科目)

**恒等式の限界を忘れない。** 会計恒等式は**スケール不変・列不変**。全部を千円で読んでも、
全部を増減列から読んでも成立する。**1000倍の単位誤りも列の誤りも通してしまう。**

## 4. 独立ソースとの突合 — 日付を合わせてから

- PDF の `資産合計` を Kabutan の `総資産` と突合する。**必ず同じ日付の列で。**
  四半期短信の当期列は3か月後の数字。**前連結会計年度末の列**が年度データと同じ日付。
  実例: 1762 を「6.4%ずれ」と誤判定した。前期列で見れば **0.0%** で一致。
- 突合が通ったら `off_pct` を記録する。**「比較対象なし」を合格と書かない。**
- **両方のソースが同じものを見落としていれば、突合は完璧に一致する。**
  実例: 9347 のノンリコースローン2,953 — 恒等式は成立(負債合計に含まれる)、
  Kabutan の有利子負債倍率とも**3.1%差で一致**した(Kabutanも除外していたため)。
  発見はPDFを直接読んだときのみ。**突合の合格は「両者が独立に同じ誤りをしうるか」を
  考えてから受け取る。**

## 5. 公表値との1件照合 — 必ずやる

計算値が外部の公表値を**再現するか**を1件は確かめる。再現したら方法が正しい。

- 予想EPS × 株価 → **公表PER** と一致するか(2914: 6,803 ÷ 362.7 = 18.8 ✓)
- BPS × 株価 → **公表PBR**
- 純利益 ÷ 期中平均自己資本 → **公表ROE**(2914: 4.72% / 12.99% と完全一致 ✓
  → 同じ方法で出した他銘柄のROEも同じ根拠に立つと言える)
- 有利子負債の合計 → **有利子負債倍率 × 自己資本**(丸めの範囲内か)
- 時価総額 ÷ 株価 = 株数、純利益 ÷ EPS = 株数 → **差は自己株式**。5%超なら本文に書く

## 6. 連結か個別か

- 通期短信には連結と個別の**両方**が入っている。
- **実効税率が異常に低い / 純利益が外部公表値と合わない表を見たら、まず個別を疑う。**
  実例: 2914 p30 は税引前495,504・純利益491,698・実効税率0.8% = 個別。連結は p11。

## 7. 丸め — 「合わない」を誤りと誤認しない

- 短信は各行を百万円単位で丸める。**行の単純合算と「計」は数百万ずれるのが正常。**
  短信記載の「計」を採用し、差は丸めと明記する(例: 1762 流動資産で3、9347 セグメントで2)。
- 恒等式の許容差は `max(2, |値|×0.1%)` 程度。**同日付の突合は1%**(丸めしか差が出ないため)。
- 表示桁は決めて統一する。0.475 を 0.48 と書くなら、本文には3桁を残す。

## 8. 欠測の扱い

- 取れないものは **`取得不可`** と書く。**代替科目を代入しない。**
  IFRS には `投資有価証券` が無い。`非流動その他の金融資産` を代入して出した数値は
  Net Cash Ratio ではなく自作の近似値になる。**注記を付けても事実にはならない。**
- ダッシュ(`－`)は 0 ではなく **None**。IFRSに経常利益は無い。
  0 として扱うと行ごと落ちる/合計が狂う。
- **「無い」と「見つからない」を区別する。** ただしフラグが抽出パターンの写しなら、
  それは自分の取りこぼしを追認するだけ。**否定形を書く前に原典を1件開く。**

## 実行チェックリスト

```
[ ] 上位ソース(通期短信)を取りに行ったか
[ ] 単位はその科目が載るページから読んだか
[ ] 科目は行頭アンカー + 表形式判定で取ったか
[ ] 4つの恒等式が成立するか(かつ、それが覆わない誤りを別途潰したか)
[ ] 独立ソースと同じ日付で突合したか。off_pct を記録したか
[ ] 公表PER/PBR/ROE のいずれかを自分の計算で再現したか
[ ] その表は連結か
[ ] 自己株式の乖離は5%以内か。超えるなら明記したか
[ ] 欠測は取得不可のままか(代入していないか)
[ ] 全数値を入力から再計算して1件ずつ突合したか
```

**最後の1行が本体。** 書いた後に全数値を再計算する検算で、実際に毎回1〜3件の誤りが出る
(丸め、グリッドの写し間違い、割合の取り違え)。**検算しないなら数字を出さない。**
