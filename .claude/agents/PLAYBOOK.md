# JP Value Screen — 運用プレイブック

`.claude/agents/orchestrator.md` を起点とした日本株過小評価株スクリーニング
Multi-Agentシステムの運用ガイド。構成そのものは `README.md`、各Agentの詳細な
振る舞いは `orchestrator.md` を正とする。本ファイルは「実際に回すときの手順と
トラブル対応」に特化する。

---

## 1. いつ使うか
- 「割安株を発掘して」「JP株スクリーニングして」等の依頼
- `/jp-value-screen`(スキル)または単に「orchestrator」という発話

## 2. 起動方法(3通り)
1. スキル経由(推奨): `/jp-value-screen [任意でセクター名や銘柄リスト]`
2. 直接依頼: 「orchestrator」とだけ発話 → スコープをヒアリングしてからAgent起動
3. 明示的なプロンプト付き依頼: 「〇〇セクターの割安株を発掘して」など

いずれの経路でも、最終的に `Agent(subagent_type: "orchestrator")` を1回呼ぶ形に
帰着させる。orchestrator自身が8専門Agentへの分岐を担当するので、呼び出し側で
専門Agentを直接指定する必要はない。

## 3. 事前チェックリスト(毎回・省略不可)

- [ ] エージェント一覧(システムリマインダー)で `orchestrator` の説明文に

      なっているかを`orchestrator.md`のfrontmatterで確認する

## 4. スコープの決め方
ユーザー指定が無い場合、以下を確認してから起動する(AskUserQuestionのテンプレ):

| 質問 | 選択肢 |
|---|---|
| 対象範囲 | 市場全体の広範なスクリーニング / 特定セクター指定 / 特定銘柄リスト指定 |
| 時価総額・流動性フィルタ | なし(Risk & Liquidity Agentが個別評価・推奨) / 中大型株のみ |

スコープを決めずに「広くお任せ」で進めると、候補ユニバースのサイズが毎回変動し
再現性が下がる。orchestrator側でも目安40〜60銘柄に上限を設けているが、依頼側
でも意図を明確にした方がよい。

## 5. 既知の失敗モードとトラブルシューティング

### 失敗モードA: Agent toolを持たないままロールプレイ代行(2026-08-29 初回発生)
- **症状**: orchestratorが「8つの専門Agentを起動した」体で結果を返すが、実際は
  単一Agentが全ステージを自分で演じていた
- **根本原因**: `orchestrator.md` のfrontmatter `tools:` に `Agent` が入って
  いなかった(WebFetch/WebSearchのみ)。ロールプレイ禁止の明示指示も無かった
- **対処**: `tools: Agent, WebFetch, WebSearch` に修正 + orchestrator本文に
  「起動前チェック」を追加し、Agent toolが無ければ**即停止して報告する**
  よう明文化(現行版で対応済み)

### 失敗モードB: 設定修正済みなのに反映されない(2026-08-29 2回目発生)
- **症状**: `orchestrator.md` を修正した直後、同一セッション内で再実行したが
  「Agent toolが無い」と正しく報告して停止した(orchestrator自身は正しく
  自己申告して停止しており、これは正常動作)
- **根本原因**: エージェント定義はセッション開始時に読み込まれ、実行中の
  セッションには動的反映されない。ファイル編集そのものは正しく反映されて
  いても、稼働中のサブエージェントには古い設定が渡っていた
- **対処**: **新しいセッション(新しい会話)を開始してから再実行する**。
  同一セッション内でのリトライでは解決しない

### 一般的な確認方法
Agentが実際に他Agentを起動したかどうかは、最終レポート冒頭の **【実行モード】**
セクション(実際に起動したAgent名と呼び出し回数の一覧)で必ず確認できる設計に
なっている。このセクションが無い・曖昧な場合は、単一Agent代行を疑うこと。

## 6. 出力の読み方
- **【実行モード】** — 実際に起動したAgentと回数。ここが無ければ疑う(§5参照)
- **【最終候補リスト】** — 優先順位付き。「総合スコア」は定性合成であり
  バックテスト未実施。投資助言(買い/目標株価)は含まれない設計
- **【見送り・注意銘柄】** — 統計上は割安に見えても除外した銘柄とその理由
  (業種相対で見ると割高、EPS質不合格、外部要因への依存が強すぎる、等)
- **【全体所感と注意点】** — 手法上の限界(網羅性、一次データ未確認等)を
  必ず含む設計。無ければ質を疑う

## 7. メンテナンス
- 専門Agentの追加・削除は `orchestrator.md` の「実行ステージ」節と対応させる
  こと(依存関係・並列化グループに反映しないと呼び出し漏れ・逐次実行による
  無駄なコストが発生する)
- 2026-08-29: 旧版で重複していた `data-collector` / `fundamental-quality-agent`
  / `catalyst-detector` / `scoring-ranking-agent` を削除。自動選択時の曖昧さを
  排除するため。復元が必要な場合はgit履歴を参照

## 8. 対象外であることの確認
このシステムは VN Market Dashboard 本体(`src/` `automation/` `public/data/`)
には一切アクセスしない。全Agentが `WebFetch`/`WebSearch` のみ(Edit/Write無し)
のため構造的に不可能。VN側の `CLAUDE.md` に定義された財務データ・表示ルールは
本システムには適用されない(適用対象が別ドメインのため)。
